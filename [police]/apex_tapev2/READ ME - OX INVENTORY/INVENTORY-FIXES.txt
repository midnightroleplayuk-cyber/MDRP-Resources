APEX TAPE — INVENTORY AUDIT UPDATE

Includes the new Field Kit UI, Rockstar Editor preparation patch, ox_inventory UseTapeItem bridge, and these inventory corrections:

1. Reusable tape (ConsumeOnPlace=false): perimeters and templates require one roll to be held, rather than one roll per span. Consuming placement still requires the full quantity.
2. Loose-end reconnection: staging the reused tape no longer requires a spare TapeItem. The existing RepairItem check and consumption still run, as do permissions, geometry, distance and any separate RequiredOxItem gate.
3. Empty TapeItem setting: placement no longer marks an uncharged span as paid. Empty item names cannot be queued as refund debts.
4. Adapter validation: invalid, negative or non-finite inventory counts are treated as zero; invalid transaction quantities are rejected.

Verified under mocked inventory/FiveM APIs: reusable and consuming costs, custom adapter parity, invalid counts, pending refunds when inventory is full, single-claim refunds, reconnection admission and paid flags.
Live FiveM and ox_inventory testing remains required.

INSTALL
Stop APEX_Tape and back up its full folder. Extract this update separately. Retain your existing config.lua, data folder and custom adapters, then replace the installed resource with the prepared folder. Start APEX_Tape and reconnect.
For item registration/use, follow INSTALL-ox_inventory.txt and merge ox_inventory-items.lua into the inventory's existing items table. Do not replace the whole items.lua file.

The default consuming setup charges one police_tape per successfully placed span, not one per entire placement session.
