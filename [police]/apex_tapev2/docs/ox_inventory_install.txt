APEX TAPE — COMPLETE INSTALL WITH OX_INVENTORY

CONTENTS
Everything is inside the APEX_Tape resource folder.
READ ME - OX INVENTORY/ contains this guide, ITEMS TO ADD.txt, police_tape.png and INVENTORY-FIXES.txt.

Includes the Field Kit UI, Rockstar Editor preparation patch, ox_inventory item-use callback, inventory audit fixes and all original streamed model assets.
The supplied config keeps Inventory.Enabled=false until you complete item registration. Enable it in step 4.

1. BACK UP AND PREPARE
For an existing installation, stop APEX_Tape and back up the ENTIRE installed resource.
Extract this package separately. Copy your existing config.lua and entire data folder into the extracted APEX_Tape folder, replacing the supplied defaults. Retain your edited server/custom.lua or client/custom_target.lua too.
Do not overwrite live saved tape with the empty data/tapes.json included for fresh installations.
For a fresh installation, use the supplied APEX_Tape folder and config.

2. REGISTER ITEMS IN OX_INVENTORY
Open your installed ox_inventory/data/items.lua.
Merge the entries from ITEMS TO ADD.txt INSIDE the existing return { ... } table.
DO NOT replace the whole items.lua file with this snippet.
If police_tape already exists, update that existing entry; do not add a duplicate key.
If scissors already exists, keep its existing definition.

The tape entry must include:
    consume = 0,
    close = true,
    client = {
        export = 'APEX_Tape.UseTapeItem',
    },

The folder name APEX_Tape and the export prefix must match exactly, including case. If you rename the resource, update the export prefix.

3. INSTALL THE ICON
Copy police_tape.png from this READ ME - OX INVENTORY folder into ox_inventory/web/images/ in your installed inventory.
Only copy the icon into your existing ox_inventory image folder.
The icon filename matches the police_tape item name. If you renamed the item, set its client.image to police_tape.png or rename the image to match.
No scissors icon is supplied. Keep your inventory's existing scissors icon if it has one.

4. ENABLE INVENTORY IN APEX TAPE
In APEX_Tape/config.lua edit the EXISTING Inventory group inside UserConfig.Settings to:

    Inventory={
        Enabled=true,System='ox',
        TapeItem='police_tape',ConsumeOnPlace=true,RefundOnRemove=true,
        CutItem='scissors',ConsumeCutItem=false,
        RepairItem='police_tape',ConsumeRepairItem=true,
    },

Keep one UserConfig table and one Inventory group. Do not paste a duplicate.
Permission framework and inventory system are independent: retain your server's existing Permissions configuration.

5. INSTALL AND START
Put the prepared APEX_Tape folder in your server resources directory, replacing the old resource after backing it up. Keep the full stream folder and fxmanifest.lua.
OneSync is required. Retain ox_inventory's existing framework and database prerequisites.
Example start order in server.cfg:

    ensure ox_lib
    ensure ox_inventory
    ensure ox_target
    ensure APEX_Tape

ox_target is optional. Include its line only if you use it; commands work without it.
After editing ox_inventory item definitions, restart ox_inventory and APEX_Tape during a maintenance window, or restart the server. Reconnect to reload client/UI files.

6. GIVE AND TEST THE ITEM
Use your existing inventory administration tools to give a test player police_tape and scissors.
Registering an item does not automatically put it in inventories or add it to shops.
Click Use on Scene Tape, or use its assigned ox_inventory hotbar slot. The Field Kit tape picker should open.
Select a design and click Start placing. Follow the on-screen placement controls.

With the shown settings:
- Opening the picker consumes nothing: ox consume=0.
- Each successfully placed span consumes one police_tape.
- Removing an eligible paid span you own refunds one tape.
- Cutting requires scissors without consuming them.
- Repair uses one police_tape.
- If inventory is full when a refund is due, it is queued; free space and use /taperefund to claim it.
- For reusable tape, change ConsumeOnPlace=false. One held roll then satisfies placement, including perimeters/templates; uncharged spans do not generate tape refunds.

Existing APEX permissions still apply. Item possession does not bypass job, duty, department or ACE restrictions.

7. MENU AND RECORDING
/changetape opens the Field Kit without clicking the item; inventory requirements still apply when enabled.
/tapescenes opens your scene board. /tapeadmin uses the existing admin permission.
If command names were customised, use the configured names.
With Editor.Enabled=true and Mode='auto', nearby standard tape prepares recording objects before filming. Wait a few seconds and record a NEW short clip. /tapeeditor status reports readiness; F8 prints missing-object details.
Runtime custom wording is excluded from recording props. Existing clips cannot gain missing tape retroactively.

TROUBLESHOOTING
No such export UseTapeItem: check the resource is started, the updated fxmanifest.lua includes client/ox_inventory.lua, and the export prefix matches the resource folder.
No Use action: verify client.export is inside the correct item entry; restart ox_inventory after editing item definitions.
Startup blocked: read the server console. Both police_tape and scissors must be registered with this setup, and ox_inventory must already be started.
Missing icon: verify the installed image is ox_inventory/web/images/police_tape.png, with exact spelling/case, then restart inventory and reconnect.
Item disappears when opening the menu: set consume=0 in the item entry and remove old usable-item handlers that also consume it.
Permission denied: check APEX Permissions in config.lua and server ACE grants.
Inventory remains disabled: when preserving an old config, explicitly apply step 4 to that retained config.
